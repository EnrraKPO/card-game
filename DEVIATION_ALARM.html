Deviation alarm · the effect system

The Hollowed Mutator

Alarm — awaiting ruling Raised: 2026-08-13 Branch: targeting-cleanup Findings: two

The implementation has left the ratified design in two places. Found while evaluating the spell work, on Enrra's question — not by audit. Nothing has been changed in response; both findings are stated here for ruling.

§1The mutator issues no mutation

TARGETING_DESIGN.md §12.6 says

The executor assembles the context and calls produce; the mutator "emits concrete StatMutations to the Arbitrator."

The code does

var dmg: int = amount.derive(feed)
Arbitrator.submit(
    StatMutation.damage(unit, dmg, holder))

payload.gd — Payload.Attack.deliver

Three things moved. The mutator no longer emits a mutation — it hands back a number. The building and submitting of the mutation migrated into the payload. And produce became derive.

The thing named for issuing mutations issues none. That is why no name for it could carry meaning — it had been hollowed out to a value supplier, and a name for a hollow thing is an empty label. The naming complaint was a symptom; this is the disease.

§2Resolvers are not owned by a world

TARGETING_DESIGN.md §3 says

"Resolver instances are owned by a CombatWorld and copied with it." A resolver holds its current — derived fresh at the two read moments, against the world that owns it.

The code does

Resolvers are parsed into TriggeredEffect, which lives on CardData — one shared, immutable definition per card, handed into world copies by reference. No world owns one; each call is passed a world: resolve(world, holder).

This one is latent: the resolvers hold nothing today, so nothing has yet gone wrong. It surfaces the moment a resolver holds anything of its own — which is what "a resolver holds its current" describes.

This is also the point I misread twice in conversation, arguing from the code instead of the design, and it cost Enrra two corrections.

§3How far it has spread

  • Contained, for now. Exactly one payload species exists (Attack), so the misplaced mutation-building sits in one method.
  • The spell work would multiply it. Every new payload species copies the shape of the existing one. Building spells before this is ruled means authoring the deviation four or five more times.
  • The design document now carries a false statement. §12.6 describes behaviour the code does not have, so the ratified text can no longer be read as a description of the system.

§4What needs your ruling

1. Nuke or repair? Whether the deviated pieces come out whole, or the mutation issuing moves back where the design put it.

2. Does §12.6 stand as intent? If the mutator is meant to issue mutations, the document is right and the code is wrong. That is the reading Enrra stated in conversation on 2026-08-13, but it has not been ruled.

3. Does the spell work wait? It is currently blocked behind this by dependency, not by decree.
