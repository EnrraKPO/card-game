Phase 1 — the world's skeleton

B1 — The Container class is named EntityContainer.

Godot refuses class_name Container: the name is a native class (verified against 4.6.3). The bible's class (Core §2) is otherwise implemented member-for-member.

B2 — The world's class is named World.

The bible names the object only "the world"; the class takes that word. The name is free in Godot 4 and in the project.

B3 — Colliding legacy class names yield to the new core. (ruled — A11)

The old GameEntity and BoardGeometry are renamed LegacyGameEntity / LegacyBoardGeometry in place, their reference sites retargeted, nothing else touched. The legacy pieces keep serving the old combat layer until they retire on the plan §3 schedule; retiring them in Phase 1 would break the running fight and the seam Phase 5 reconnects to. The struck rationale was corrected in review (the fight is non-functional; what the staging preserves is compilation of the 60 reference sites) and the disposition is now ruled by AMENDMENTS.html A11: legacy is tolerated only until the replacement is complete, then exterminated whole at the Phase 5 swap.

B4 — Stat values are stored as float.

The strike numbers include the crit multiplier ×2.0 (Mutation §7), so the stat domain is fractional. Authored quantities and deltas stay int as the markup rules (Mutation §4).

B5 — Spellings the documents leave unnamed.

The A4 allegiance member is named allegiance (A4 rules the fact, not the member's name; side would shadow the Side class). A Status bears status_id — the id has_status reads (Core §9). The Phase 1 stat ids, per the signed statements that name them: round (Game); mana, mana_capacity (Side); cost (Card); attack, health, speed, shield, tapped (Unit); stacks (Status). Stats named by later phases (the strike numbers, the frame's seeds) land with their consumers.

B6 — A Side's allegiance is itself; the Game's is null.

A4 stamps every entity's owning Side at construction and rules neither edge case. Self answers is_ally/is_enemy for side-held holders; null states the Game belongs to no side.

B7 — The board address form.

An address is Vector3i(side, row, col); the half index matches the sides container's order (player 0, enemy 1), which is the identity read (World.player_side() / enemy_side()). The board's shape — ROWS 3 × COLS 4 per half, the current board's facts — lives as constants on BoardGeometry, whose mirroring arithmetic depends on it.

B8 — The AOE shape definitions (Core §3 names the shapes, not their extents).
  • row / column — every cell of the origin's half sharing the origin's row / column.
  • radius — every cell within r by the symmetric distance, both halves, origin included.
  • square — every cell within r on both axes of the unified depth/lane space (Chebyshev), origin included.
  • cone — spreads toward the facing half: at forward step d (1..reach), the cells d columns ahead within lane offset d; origin excluded.
B9 — Mint's concrete act.

The existence primitive stamps the entity's world back-reference — an entity exists in a world from that stamp. The minted entity is unhoused until a membership write houses it; allegiance is stamped by the constructor, as A4 states.

B10 — The PresentationOutlet base is the deaf outlet.

One class: the base receives every cue and plays nothing — the simulated world's outlet as-is; the live presenter subclasses it at the Phase 5 seam. The cue signature (visual name, recipient, magnitude) is provisional until the conductor and the procedures pin it in Phases 2–3.

B11 — GameEntity.effects is untyped until Phase 3.

The member the bible states (Core §1) exists now; its element type is the Effect class, which lands with the rules machinery — the annotation tightens the moment the class exists.

Phase 2 — the write road

B12 — The stat write carries the authority's events out by a required parameter.

stat_write(entity, stat, value, events) — the authority's fact events (died among them) append to the caller's collection; events travel by return (Mutation §8), and a discarding default would lose a death silently.

B13 — Sources of the new fact events.

damaged and died — the entity it happened to; dodged — the dodging defender; crit — the critting striker; the engaged events — the asked entity, from the request (Core §8 states only the last).

B14 — The damaged event's facts, and death's place in the return order.

damaged carries one StatMutationEventData per committed write (shield, health), zero-delta writes omitted; the authority's died follows damaged in the returned order.

B15 — Health is unfloored; died is the crossing.

No ruling floors health; died is produced when a write takes it from above zero to zero or below — once per crossing, not per write below zero.

B16 — Strike arithmetic rounding.

The strike's amount is roundi(attack); a crit's amount is roundi(amount × multiplier), the multiplier first capped by its cap stat. "Damage after mitigation" (the crit gate) reads: amount minus the defender's shield, above zero.

B17 — The strike numbers seed in code.

Game's construction seeds the §7 ruled values (dodge 0/1/4/75, crit 5/1/0/75, ×2.0 cap ×5.0) with the stat ids dodge_base, dodge_speed_rating, dodge_difference_rating, dodge_cap, crit_* likewise, crit_multiplier, crit_multiplier_cap. "Seeded from data" resolves to a data file when the frame's genesis lands its seeding road.

B18 — Move events enter when content asks.

ContainerMoveRequest members: destination_owner + destination_container. Only fielded is produced today (its condition and stamps as ruled, Core §2); other moves bear no event yet — a general move event's name is deliberately unminted.

B19 — PayCostRequest carries the engaged name.

Members beside mana/tap: engaged_name and ability (empty for a play). Requests are self-sufficient and the occasion-derived event name (Core §10) must ride in; the elected targets do not ride — the delivery appends them (Core §8).

B20 — Status grant details.

Tap spend increments tapped (pay of tap N = tapped + N). A minted status's starting stacks are its construction seed; later grants go through the stat write. The minted status's allegiance is stamped the target's — it lives on the target's side of the world. ⚠ Flagged for ruling: an inflicted status could as defensibly belong to the inflictor; nothing in the slice reads it yet.

B21 — The building birth fact is a Unit member.

Unit.is_building, false unless authored (envelope A7), set at construction; the strike's buildings-never-dodge rule reads it.

Phase 3 — rules and flow

B22 — Resolver and decision details the sections leave open.

The candidate field is the world's ownership tree walked whole, in declaration order — the deterministic order ties fall back on. Nearest and stat-ranked elect ONE (nearest ties break by address reading order; stat-ranked to the earliest candidate; unrankable candidates fall out); random elects one uniformly from the world's rng. The deck's top is its first member; a draw from a shorter deck draws what exists. BoardManager gains address_of — the fetch map's inversion. The authored targeting form (under A7's delegation): {"decision": name-or-object, "conditions": [...]}, decision parameters required like the mutator roster's.

B23 — The pay mutator's amounts.

Members mana (−1 = read the holder's cost stat at issuance — the play's form) and tap; an ability's expansion fixes its authored cost here. The engaged-name derivation from the occasion lives in this mutator, as Core §10 places it.

B24 — The flow layer is coroutine-native.

Engage, the picker's pick, and the conductor's flow beats (windup, contact, conclusion — Mutation §11's awaited cues) are coroutines: the live picker and presenter await the player and the VFX span. The deaf bases greenlight on the spot, so a simulated world runs synchronously. The engine road (submit → procedures → authority) stays strictly synchronous.

B25 — Turn order's single definition, and its home for now.

CombatCascade.turn_order(world) holds the activation comparator until the clock lands (the frame doc gives the clock the compute-once duty; the definition stays one). It reproduces the pre-nuke oracle exactly — speed desc, player on ties, forward column depth desc, then row DESC — with slot rank and container position closing the total order.

B26 — Trigger markup details.

Policies validated to all/any; role-name routes pass unvalidated (the role vocabulary is open); condition members default where unauthored — the required-every-parameter rule is the mutator roster's (Mutation §4) and, by B22, the decisions'.

B27 — Who writes the accretion.

The Mutator base appends its kind (role mutator_kind) to every event its issuance returns; the conductor appends the delivery's elected targets (role targets) to every holstered event — engaged events included, which is how play_engaged carries the play's targets.

Phase 4 — the card roads

B28 — The baked machinery's details.

The route-source + is_holder entry is baked on the play and use effects too — without it every card's play would answer any play ask (the §5/§7 discrimination, entailed). The baked conditions live together in BakedConditions (machinery, not authored vocabulary): one affordable definition serves the play trigger, the use trigger, and the payability query; a tap price is affordable while the holder is untapped. The Unit play's default pick narrows to VACANT slots of the holder's own side. Machinery built-ins whose duty begins off-board — play, placement, burial — carry the implied fielded condition removed.

B29 — The ability form's details (under A7's delegation).

{"name", "cost": {"mana", "tap"}?, "targeting", "effect": {"payload", "targeting"?, "windup"?, "contact"?}} — cost absent = free (Move's shape); the substantive effect's targeting defaults to the stock occasion's-targets form; a trigger inside the effect body is a stranger — the expansion owns both triggers. Borne ability names live in GameEntity.abilities — the ask capability made readable.

B30 — Orderings the effect-list order decides.

A holder's machinery effects precede its authored ones (construction first), so a spell's burial reacts to play_engaged before its substantive effect — the spell strikes from the graveyard, lawfully (its effects still exist). Likewise a unit's burial precedes its own authored death reactions, which therefore need the implied fielded condition removed to fire. Unit.new(side, building) — the building birth fact became a constructor parameter so the Move appointment (A9) can read it at construction.

B31 — ⚠ The deck has no gather bucket.

Mutation §2 names deck cards in the cascade's audience; §12's bucket table has no deck bucket. The gather follows the table — deck-held effects are not polled today. No slice content holds one; flagged so the bucket enters by amendment the moment content demands it, not by my weight guess.
