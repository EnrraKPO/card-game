Core System Tech Brief

Hierarchy

  • GameEntity = root. Every GameEntity: holds effects, bears stats, holds a container map, bears a back-reference to its world.
  • Direct subtypes: Game (the base rules and their stats), Side (mana stat; containers below), Relic, Upgrade, Status, Slot, Card.
  • Card subtypes: Unit, Spell.
  • The world: the object holding the game state. It holds the roots (Game, the two Sides, the run's holders), embeds the BoardManager, owns the presentation outlet and the seeded rng, and is what simulation copies.
  • Slot coordinate: row + column within its half; set at construction, immutable; no side component. A slot's side = the side owning the board container housing it.
  • Any GameEntity is a legal target. Narrowing = resolver conditions only.
  • Type-embedded machinery — Card: play effect, payability query. Unit: main action, target poll, placement effect, unit burial effect. Spell: spell burial effect.

Containers

  • One Container class for every use. Members: owner: GameEntity, name: StringName, members: Array[GameEntity] (ordered).
  • Per entity: a map name → Container. Access: get_container(name), get_container_list(). Container.name duplicates the map key; the membership primitives maintain both.
  • Container names are declared per type, like stat ids. GameEntity declares contained; Side: deck, hand, graveyard, board; Slot: slotted_unit. Parse refuses a name the authored subject type does not declare. Remaining types: Open 2.
  • Occupancy: a unit is fielded in a slot ⇔ it is a member of the slot's slotted_unit. Current content: one unit per slot; mechanics carry any count.
  • Back-reference: every housed entity references its Container. Written only by the membership primitives (insert, remove). Board position read: my container's owner's coordinate.
  • One housing: an entity is in exactly one container, or none (newly minted). A move = remove + insert, one procedure.
  • The container-move procedure stamps origin and destination housings as EventData on its event. Origin conditions read that component; the mover's current housing is a separate world read.
  • Any insert into a slotted_unit produces the fact event fielded (source = the arriving unit; origin + destination stamped). Every route onto the board passes through this insert.
  • Mover mutator addressing: destination = owner + container name; the name resolves through the owner's map. The recipient is the destination's owner. The name is fixed in the mutator kind where the kind serves one destination (placement → slotted_unit, burial → graveyard), else a declared typed member. A container is never a recipient.
  • Membership legality lives in the writing procedures.
  • Implementation: weak back-references; world copies remap both ends of every housing relation.

Board and geometry

  • Each side owns a container board housing its half's slots.
  • BoardManager: one per world, embedded in it. At world birth, one act: mint both halves' slots, stamp coordinates, house them via the membership primitives, file the index. Fetch: address → slot, a direct map built once, never rebuilt; plus a multi-address fetch. It computes no shapes and owns no comparator.
  • Geometry class: pure static functions, stateless, no world access; coordinates + the halves' facing relation in, coordinates out. Name: open. Members: symmetric distance (no facing); attack-preference comparator (facing as input; acceptance: reproduces current orderings); AOE shapes cone, row, column, radius, square. All half-mirroring arithmetic lives here only.
  • Resolver composition: conditions narrow by entity facts → decision ranks by a geometry function → addresses → manager fetch → slots → occupancy via the slot's container.
  • Allegiance = birth fact. Standing half = the slot's housing owner. The reads may differ; each answers truthfully.

Target resolver

  • Job: elect the payload's recipients. Inputs: the plate (occasion, holder; world via holder) + each candidate as the typed subject.
  • Structure: conditions (narrow to eligible), then decision (pick). Decision family: nearest, random, stat-ranked, hand-pick, occasion's-targets. Hand-pick = a decision that consults the player.
  • Resolve phase: side-effect-free; deterministic narrowing only; any reader runs it at any moment (target poll, preview world, greyout).
  • Engage phase: unknowns settle once, in the live flow — rolls from the world's seeded rng, the picker picks. Issued uniformly for every resolver; nothing-unknown resolvers answer from their resolution. Engaging triggers payload delivery.
  • Declined pick = empty election: the effect does not trigger, the payload never runs; an activated ask ends whole, unpaid.
  • No authored resolver → the effect targets the Game; fixed at construction. An empty election ends the delivery.
  • Elected targets ride the delivery's produced events as EntityEventData, role targets; a singular target = a set of one. Derivations ("adjacent to the occasion's targets") = resolver conditions reading the occasion.
  • Unique mutator: a kind-declared quality. The conductor runs it once per delivery, before the recipient walk, null recipient on the plate; it appoints its own target from the plate.

Play road

  • Every card bears the play effect. Trigger: play, source = the card. Baked conditions: affordability (cost stat within open mana), holder-in-hand; authored conditions join. Targeting: authored; type defaults — Card: automatic/Game; Unit: manual/Slot. Payload: the pay mutator — unique; recipient = the holder's side; pays mana.
  • Cost = a card stat, seeded from the authored form at construction, mutable through the write road.
  • Payment produces play_engaged, carrying the elected targets. Substantive effects: trigger play_engaged, gate route source + is_holder; the stock resolver takes the occasion's targets, authored resolvers derive by condition.

Built-in effects

  • All three gate: entity entry, route source, condition is_holder.
  • Unit placement: trigger play_engaged; resolver = stock occasion's-targets (the play's slot); payload = placement mutator: container move of the holder into the slot's slotted_unit; the insert produces fielded.
  • Unit burial: trigger died; payload = burial mutator: container move to the side's graveyard. died = fact event, WriteAuthority-authored; every road to zero health produces it.
  • Spell burial: trigger play_engaged; payload = burial mutator.
  • Burial reactors gate on the stamped origin housing, not the moved entity's current housing.

Abilities

  • Ability = the holder's capability to have an event fired at it at will. Any GameEntity may bear one.
  • Event grammar: asks imperative (play, use_heal); happenings past tense (play_engaged, use_heal_engaged, died). An ability's two event names derive from its name. The ask carries no components.
  • Appointment expands at construction into: the ask capability; the use effect (play-effect structure: trigger the ask, affordability + authored conditions, authored targeting, pay-mutator payload; produces the engaged event with targets); the substantive effect (authored; trigger the engaged event; gate source + is_holder).
  • Discrimination: the event name identifies the ability kind; is_holder binds the instance. Both wired by the expansion.
  • The pay mutator derives the engaged name from the occasion's ask name: play → play_engaged, use_heal → use_heal_engaged. One derivation, both roads.
  • Authoring: the markup form only. Fields: name, cost, targeting policy, substantive effect. Expansion is programmatic.
  • Play effect: Card machinery, one per card. Use effect: minted per appointed ability. Same structure.

Events

  • Event = core + components. Core: source (any GameEntity), name. Components: Array[EventData].
  • EventData: a typed class family, one class per fact shape — StatMutationEventData (stat, delta), MutatorEventData (mutator kind). Same shape, new purpose = same class; purpose is a name.
  • EntityEventData: role: StringName + entities: Array[GameEntity]; a singular fact = a set of one.
  • Accretion: each road layer appends its components — a mutator its MutatorEventData, a delivery its targets, a procedure its happening's facts. Open to anything on the road.
  • Read: fetch by component class → all matching components; the reader governs multiples.
  • A condition on an absent component = false. Provenance: source answers who; MutatorEventData answers how.
  • The trigger names the event; the naming is itself a condition of the effect.
  • Ask event source = the asked entity. Engaged event source = the same entity, stamped by the procedure from the request.

Conditions

  • Condition = predicate: one question, true/false, writes nothing.
  • Two seats: effect gate (trigger naming + authored conditions; all must hold) and resolver (narrows candidates).
  • Inputs: the plate (occasion, holder; world via holder's back-reference) + a typed subject supplied by the seat. Mutators receive the same plate; their recipient is likewise a separate typed input.
  • Families by subject type: EntityCondition (GameEntity), EventCondition (Event). No shared evaluate. A shared base above the families carries: kind id, negate, declared typed members + parse, stateless-immutable lifecycle. A new subject type founds a new family with its own routes (the container = the standing case). Growth: Open 8.
  • Gate routes for EntityConditions, closed list: source (set of one), holder (set of one), eventdata (all EntityEventData entities pooled; or a role name → that role's entities; absent role = empty set), world (every entity). The effect owns the fetch; EventConditions carry no route.
  • Gate = two typed lists, sorted at parse: EventConditions, entity entries. Holds when both hold; an empty list holds vacuously. Each list: policy all/any.
  • Entity entry = route + conditions (conjoined per entity) + negate. Fold = any: the entry holds when some yielded entity satisfies every condition. The entry negate inverts the folded answer (existential → universal: "all enemies wounded" = not-any(enemy, healthy)). No other fold.
  • Authored form: 
    "gate": {
  "event":  { "policy": "all", "conditions": [
    { "kind": "mutator_is", "mutator": "poison" }
  ]},
  "entity": { "policy": "all", "entries": [
    { "route": "source", "conditions": [ { "kind": "is_holder" } ] },
    { "route": "world", "negate": true, "conditions": [
      { "kind": "is_enemy" },
      { "kind": "stat_vs_stat", "left": "health", "op": "lt", "right": "max_health", "negate": true }
    ]}
  ]}
}
    Route tokens: source, holder, world, eventdata, or a role name. Defaults: policy all, negate false, absent list = empty (holds vacuously). Kinds beyond the roster are illustrative.
  • Kind authoring: content selects a kind id and fills its declared typed members — { "kind": "stat_compare", "stat": "strength", "op": "gt", "value": 5 }. A new check = a new class in the subject's family + one kind-table row. Combination vocabulary: the two list policies, the base negate, the entry negate, the entry any-fold. A condition holding conditions does not exist.
  • Negate: base member, bool, default false; the machinery inverts the kind's natural answer. Over an absent component the inverted answer = true.
  • Roster: is_holder (EntityCondition, no members; subject == the plate's holder); has_status (EntityCondition, status_id: StringName; subject's contained holds a Status of that id, checked downcast). The baked conditions (affordability, holder-in-hand) are machinery, not roster entries. Growth: Open 8.
  • Stats: identity = id (StringName). Each type declares two lists: public mutable, read-only. Parse refuses an id undeclared on the authored subject type. Execution refuses at the concrete bearer: unborne id, or write to read-only.
  • Lifecycle: constructed at parse, immutable, stateless; one instance shared across card copies and worlds. Anything needing memory = a world fact.
  • Parse: one generic driver. Kind id → class via a static table; members filled by name; unknown keys and type mismatches refused loudly; serialization = the mirror walk. Members parse into their real types; no text survives parse and no later checking layer exists.
