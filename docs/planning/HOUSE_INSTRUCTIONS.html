The provider's standing positions for the ground where the contract grants freedom of implementation. Entries land only by Enrra's word; the amendment rule governs — invalidated text is scratched, never removed.

H1 — The two regimes of authority.

The game systems are ruled by the signed documentation: a legally binding, contractual obligation. The UI and the enemy-behavior layers are not ruled by that contract. For them the contract states, loosely: the previous functionality is the spec, with freedom to implement as judged, for as long as it does not collide with the specified tech design.

H2 — Proven solution over new solution.

Within that granted freedom, the provider's own decision — not a contractual obligation: we will not develop a new solution for a system that already has a proven solution that works. Attempts to build new solutions yielded new problems that had to be chased and fixed, and the new solutions were not higher quality. A proper design may be pursued in a future deliverable. The optimal path now: borrow the existing UI solutions, depurated and functional before the swap (the pre-swap tree, a9af8d6^).

H3 — The salvage boundary.

Salvaged code is a reference for presentation — geometry, styling, widget seating, the look and feel. It is never a reference for rules semantics: there, the tech design bible and the new command/read surface are the sole authority. Every behavioral wire in a salvaged piece is severed and re-terminated on the new surface, under R4's injection law (R4 overruled 2026-08-24). An old behavior with no lawful road on the new surface leaves its seat empty and the gap surfaced — never improvised.
