The Main Action

Signed — 2026-08-13 Date: 2026-08-13 Branch: targeting-cleanup Open questions: one — §8, deferred by ruling to its own future cycle

Nothing below is implemented. Every statement stands on the 2026-08-13 conversation and the signed TARGETING_DESIGN.md alone; nothing stands on the cursed additions of ATTACK_SYSTEM_DESIGN.html.

§1The problem

Presentation must illustrate each unit's decision — whom it would strike — while play waits for input: the crosshair and menace cues. To answer, it needs to know each unit's main action and ask that action for its current targets.

But under the current design, "this is the unit's main action" would live in two places at once. The effect's authored trigger ("fire when I act") decides what actually happens when the unit acts. A separate appointment would decide what the unit claims outward for target polling. Nothing ties them together: it is materially possible to appoint effect X while effect Y is the one that fires — and presentation would then illustrate an action that never occurs.

Two independent statements of one truth, kept consistent only by authoring discipline. Discipline is policing, and policing fails at one discretional call.

§2The principle

The appointment is the single authority. A main action is not "an effect bound to the act event" — it is the effect appointed as THE main action of the unit. Everything flows from that one fact.

Both consequences read the same appointment, so drift is unwritable:

  • The main action is what fires when the unit acts — bound to the act through the appointment, at runtime, not through an authored trigger.
  • The main action is what the target poll answers for.

The event is not the distinguishing thing. "Act" remains ordinary trigger vocabulary: any triggered effect may bind to it, and that is just a normal effect reacting to a normal event — a bystander, not a rival authority. It makes no claim to being the main action, so it cannot drift against it.

§3The two kinds of effect

Today every effect is a triggered effect: when [trigger], deliver [payloads] to [targets]. This design adds a second kind — the card action — differing in exactly one slot: who owns the "when."a3 The card action is not a sibling kind of effect but a trigger kind — see amendment 3; the concept below survives with that correction.

The triggered effect

Owns its own "when": an authored trigger, fixed at parse, part of the effect's definition. Events arrive, the trigger answers "do I fire?" — unchanged, for every event, forever.

The card action

Owns no "when" at all. The slot is not a different kind of trigger — it is absent from the effect and owned by the card.a3 The card's runtime appointment is the only thing that fires it. Everything else — targets, payloads, appointed presentations — is the shared body both kinds carry.

The two dispatch paths are disjoint, decided at parse by kind: a card action never enters the trigger-matching pool (there is nothing in it to match), and a triggered effect can never be appointed as a main action (it is not of the appointable kind)a3 and only an Action-kind trigger makes its effect appointable. No flag, no runtime condition, no discipline — each path structurally cannot carry the other kind.

At this scope, only the five attack effects become card actions. Candidacy is not the mechanism — explicitness is: any future effect authored as an action qualifies the same way.

§4The machinery

One piece of machinery on the unit — the main-action holder — is the single authority on "what this unit does." It has three duties:

  1. Fire on act. When the unit acts, the holder fires the appointed main action.
  2. Answer the target poll. "Who are my main action's current targets?" — see §5.
  3. Serve as the entry point for switches. When main actions become switchable at runtime, the switch lands here and nowhere else. Its semantics are §8's open question; only the entry point is ruled now.

The main action is a runtime fact: the card is the authority on its current main action, and the poll's contract never changes when switching arrives.

The auto-appointment rule: a unit with exactly one action needs no ceremony — that action is immediately its main action. A unit with more than one action has exactly one active at a time.

Every current unit has exactly one attack, so nothing per-card is authored anywhere: no per-unit stamp exists at this scope, and none is needed until multi-action cards exist.

§5The target poll

The card exposes one query: "who are my main action's current targets?" It is answered internally — the card consults its main action, the action consults its own target resolver — and the answer is entities only. No effect-shaped object, no resolver, nothing with readable insides ever crosses outward. The effect stays sealed exactly as the signed presentation charter demands: the card activates it and polls its appointed targets, never opens it.

The poll costs nothing to keep honest, because the answer is never stored: TARGETING_DESIGN.md's ratified ruling (2026-08-11) already defines a resolver's current as computed fresh at the moment someone reads it, at exactly two read moments — the trigger moment, and the interactive idle. The poll is the second read moment: presentation computes every unit's main-action targets while play waits for input, and illustrates the decisions. The board that answering happens against is the resolver's own concern (resolvers are owned by a CombatWorld and query it) — never the poller's.

Authoring an action must be unmistakable — the authored form itself says what kind of thing it is.

Since a card action owns no "when," its honest authored form has no trigger member at all.a3 In the trigger's place stands the declaration that it is an action. The absence is not an omission to tolerate — it is the marker itself.a2 The kind is declared by which form is authored — see amendment 2.a3 The kind is declared by the trigger's own kind: "trigger": {"kind": "action"} — see amendment 3.

Amendment · iteration 2 · 2026-08-13

Ruled by Enrra in conversation after the iteration-1 read (pre-signature). Where a ruling below contradicts anything above, the ruling below governs. Scratched text in §6 marks the statements this amendment invalidated, each tagged a2.

The kind is declared by the authored form, not by a marker member a3 — superseded whole

The sibling type itself suffices; no field inside the effect states its kind. Triggered effects and card actions are two authored forms, and which form is written declares which kind parses:

— The triggered form is today's, unchanged: the trigger member is required, its absence refused loudly. A triggered effect that forgot its trigger is a caught mistake, never a silent action.

— The action form has no trigger slot at all: a trigger member appearing there is a stranger, refused loudly like any other stranger.

Each form refuses the other's members, so neither kind can be written to look like the other. The five attack effect files simply are action-form files — they drop their trigger member, and nothing else is authored.

Supersedes §6's "the absence is the marker itself," §6's both-members contradiction rule, and rejects §6's proposed "action": true marker whole. Amendment 3 (2026-08-13) supersedes this ruling whole — the required-trigger rule it stated survives trivially under amendment 3: the trigger member is always present, in both kinds.

Amendment · iteration 3 · 2026-08-13

Ruled by Enrra in conversation after the document was reopened (2026-08-13, the same day as signature), prompted by two implementation-blocking gaps: how a reader tells the two authored forms apart, and where the attack files' untapped gate lives once their trigger is gone. Where a ruling below contradicts anything above — amendment 2 included — the ruling below governs. Scratched text in §3, §6, §7 and amendment 2 marks the statements this amendment invalidated, each tagged a3.

The action is a trigger kind, not a sibling kind of effect

There is no second kind of effect. Every effect remains a triggered effect — when [trigger], deliver [payloads] to [targets] — and the trigger vocabulary gains a third kind alongside Simple and Dual: Action.

The authored form: "trigger": {"kind": "action"} — nothing further inside it. It names no event and carries no conditions; any further member appearing inside it is a stranger, refused loudly. An Action trigger listens to no event on its own — dispatch never fires it; only the appointment does (next ruling).

Both gaps close at once: the trigger member is always present, in both kinds, so a missing trigger stays a caught mistake — never a silent action — and the kind is read where every trigger's kind is already read. No absence to interpret, no field added to the effect body.

Supersedes §3's "second kind of effect" and its absent-slot framing, §6's "no trigger member at all," and amendment 2 whole.

Appointability flows from the trigger kind; the appointment binds and gates

An effect whose trigger is Action-kind is thereby appointable as a main action — automatically, with no further spec. The appointment — not the authored trigger — binds it to the act event, and gates its firing on untapped as a condition: a tapped unit's main action does not fire. Nothing about this is authored per card or per file; §4's auto-appointment rule and the holder's three duties stand unchanged.

The five attack effect files author "trigger": {"kind": "action"} in place of their act trigger; the authored untapped condition leaves with it — the appointment now carries that rule. Everything else in them — targets, payloads, appointed presentations — stands untouched. Five files, nothing else authored: §6's scope survives.
