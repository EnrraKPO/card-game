A15 — The source is mechanical.

An entity-fired event carries the firing entity as source. A mutation's fact events carry the request's source — the holder of the effect that minted the request — shared across every event of the one context. Burial's entry and Core §8's authored example route target, condition is_holder. Lands on Core §6, Core §8, Mutation §7–§8. Ruled by Enrra, 2026-08-25.

A16 — The target is native.

An event carries a target in its core: one GameEntity, at all times. The target is the Game until a resolver elects one. The target propagates into the branching events the cascade produces, and forwards into requests, which carry it until they appoint a new target. An effect without a targeting block falls back to the generic AutoResolver: it resolves as the target carried in context, falling back to the Game where none is found. EntityEventData is demoted from being a core mechanism, in favor of the native event target. Lands on Core §4, §8, §9; Mutation §6. Ruled by Enrra, 2026-08-25.

A17 — Decoupling of container move logistics.

A move op elects the destination entity as its target; the mutator introduces the cargo into the MoveRequest. The Move ability's MoveUnitMutator and the play's PlacementMutator each introduce the holder as cargo — the same operation, each its own stake. Where the entity being moved is the target, the request is routed to its specific-purpose procedure (DrawProcedure, BuryProcedure). The spell's burial effect carries a holder-electing resolver, fixed in its machinery; unit burial rides the AutoResolver. Lands on Core §2, §6; Mutation §4, §7. Ruled by Enrra, 2026-08-26.

A18 — The substantive rides the ask.

The substantive mutators of play and use_ability ride the paying effect itself, alongside the payment. The pay mutator is unique; the remaining mutations route through the effect's target resolver. Placement is a baked-in substantive mutator of the unit's play. Lands on Core §5, §6, §7; Mutation §11. Ruled by Enrra, 2026-08-26.

A19 — The request rides the event.

Every event originated from a mutation request path stamps the request at hand as a RequestEventData. Events do not carry the mutator_kind as a separate component. Supersedes A15's carriage sentence (the request's context riding under its members' names) and Core §8's mutator-kind accretion line. Lands on Core §8; Mutation §6–§7. Ruled by Enrra, 2026-08-26.
