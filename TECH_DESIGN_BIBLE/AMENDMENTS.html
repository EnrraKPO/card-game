A1 — The geometry class is named BoardGeometry.

Ruled by Enrra, 2026-08-23. Closes the naming open of Core §11; lands on Core §3.

A2 — The win condition: killing the enemy's king ends the fight in victory.

The enemy's king (the captain) dying is the win condition. Ruled by Enrra, 2026-08-23. New ground — no prior section states it; it lands with the fight frame's document when that is authored.

A3 — The Move ability: free, asked by the existing moving UI.

Moving costs nothing in this version. The use_ability ask for Move is fired by the moving UI already in place; that UI is adapted as needed to obtain the target slots and fire the event — the old system carries the desired functionality. Ruled by Enrra, 2026-08-23. Lands on Core §7 and the placement mutator's row (Mutation §4).

A4 — The allegiance fact is a direct reference to the owning Side.

Every entity bears a member referencing the Side it belongs to, stamped at construction as a birth fact and never rewritten. The read "the holder's side" — the pay mutator's recipient among its users — returns this member. World copies remap it under the established reference discipline. Ruled by Enrra, 2026-08-23. Closes the allegiance open of Core §11; lands on Core §3 and §5.

A5 — Command order, and when a fielded unit first acts.

Within a round, the enemy commands first, then the player. A unit acts in the first combat span after it is fielded — fielded during a round's command span, it acts in that same round's combat span. Ruled by Enrra, 2026-08-23. Lands with the fight frame's document, beside A2.

A6 — The main action and the target poll.

The combat span's clock fires the ask event act at each fielded unit in speed order. The main action is fixed Unit machinery with the standard effect structure: trigger — event act, the route-source + is_holder entry, and the baked condition that the unit is untapped (not exhausted); targeting — the attack resolver, deciding by BoardGeometry's attack-preference comparator, electing one enemy unit; payload — the strike mutator. Acting has no cost: no pay mutator, no engaged pair — the action triggers directly on the ask, and the strike procedure's events are the happening record. The target poll is this resolver's resolve phase, run at interactive idle for the previews (Core §4). Ruled by Enrra, 2026-08-23. Lands on Core §1's Unit machinery and with the fight frame's document.

A7 — The card file's envelope (ruling delegated).

One object per card: identity (id, display name); kind (unit or spell, deciding the constructed type); stats as a name→value map seeding construction, validated against the type's declared lists; birth facts where the type bears them (building, elements); effects — a list of the bible's effect markup (trigger, targeting, payload); abilities — a list of the Core §7 ability form. Relics and statuses use the same envelope minus kind. Parsing is the Core §9 generic driver at file scope — strangers refused loudly. The slice authors new files in this envelope; the existing catalogue converts at the parity migration. Approved conditionally by Enrra, 2026-08-23 — the ruling's detail is delegated to the contractor's judgment; deviations of detail within this envelope are lawful, its outer shape is ruled.

A8 — Roster growth for the slice.

The condition roster (Core §9, Open 8) gains:

  • name_is — EventDataCondition, members role and name; true when the occasion carries a NameEventData of that role bearing that name. States the kind the §9 example and the baked ability-name condition already use.
  • is_ally / is_enemy — EntityCondition, no members; the subject's allegiance (A4) compared to the holder's.
  • is_unit — EntityCondition, no members; a type check.
  • houses_me — EntityCondition, no members; true when the subject owns the container housing the holder.

Open 2, for the slice's types: no container is added beyond the declared — statuses ride contained (Mutation §7); the open stays open for future content. Ruled by Enrra, 2026-08-23. Lands on Core §9's roster and §2.

A9 — Move's appointment.

Machinery appoints the Move ability on every unit at construction — conditionally: buildings do not receive it. Ruled by Enrra, 2026-08-23. Completes A3; lands on Core §7.

A10 — UI is out of the contract's scope.

UI is out of scope for the contract, with the only rule being: the pre-nuke functionality is the requirement. Partial functionality through iteration is allowed — while the work iterates, UI features may be non-functional, partially functional, or broken. Ruled by Enrra, 2026-08-23.

A11 — Legacy disposition: tolerated until replaced, then exterminated.

Legacy classes are tolerated until the non-legacy versions are completed; then the legacy ones get exterminated. The replacement is implemented to full extent before the swap: Phases 2–4 build it whole; Phase 5 rewires every reference site and cleanses the demoted layer in one stroke; the plan proceeds only past a codebase bearing no legacy trace. Non-combat code standing on demoted classes is part of the cleanse. Supersedes the plan §3 per-phase retirement. Ruled by Enrra, 2026-08-23. Lands on IMPLEMENTATION_PLAN.html §3.

Signature: signed off — Enrra, 2026-08-23.

A12 — The presentation beats carry the source.

The outlet's flow beats (Mutation §11: windup, contact, conclude) grow the acting holder: the conductor hands the effect's holder to each beat beside the presentation name and the recipients. Without it the presenter cannot play the cause half of a happening (the source's glint, the lunge, the bolt flying from actor to victim); with it, cause→effect reads become expressible. The procedures' fire-and-forget cue keeps its shape (name, recipient, magnitude) — this amendment touches the beats alone. Lands on Mutation §10/§11. Ruled by Enrra, 2026-08-24.

T1 — Composition is an immutable birth fact.

At this scope, a unit's composition enters through the card envelope's birth facts (A7's elements) and never changes; the merge system stays untouched; no mutation reaches composition. Future work makes composition condition-eligible and mutable — it fits the existing ontology (counts-as stats or members) and receives its own ruling when it comes.
